# Anvaya Films CRM + ERP — Technical Specification
### Version 2.0.0 (Draft) — Revised from v1.0.0 feature list

This document replaces the original feature-list spec with an engineering-ready
specification: one schema per sheet, explicit relationships between sheets,
and defined automation logic. It assumes the system stays single-file Excel
(.xlsm) for v1, with the multi-user question called out explicitly in
[§0 Open Decisions](#0-open-decisions).

---

## 0. Open Decisions

These need an answer before build starts — they change the schema below.

| # | Decision | Options | Recommendation |
|---|----------|---------|-----------------|
| 1 | Concurrent multi-user editing? | (a) Single user at a time, file on local disk (b) Shared file on OneDrive/SharePoint, co-authoring (c) Split into per-role workbooks that sync via Power Query | If >1 person edits same day, use (b); accept that VBA macros disable co-authoring, so heavy-macro sheets should be minimized |
| 2 | Client : Booking cardinality | One client = one booking, or one client can have multiple bookings (e.g. engagement + wedding + reception booked separately) | Assume **one-to-many** (Client → Bookings) — matches real usage |
| 3 | GST logic | Flat 18%, or CGST+SGST split, applied to which line items | Assume flat 18% on invoice subtotal unless told otherwise; flag as config value, not hardcoded |
| 4 | What "Security" actually protects | Accidental formula edits vs. protecting financial data from a specific role | Assume: sheet protection = accident prevention only. Not a substitute for real access control. State this to the client. |

## 1. Data Model Overview

Core entity relationships (1—* unless noted):

```
Lead ──(converts to)──> Client ──< Bookings >── Wedding Event
Booking ──< Payments
Booking ──< Team Allocation >── Team Member
Booking ──< Production Pipeline (1:1 per booking)
Booking ──< Album Tracker (1:1, optional)
Booking ──< Equipment Assignment >── Equipment
Expense ──(optional link)──> Booking (for job-costing) or standalone (overhead)
```

Every child sheet stores its parent's ID as a foreign key column (never a
lookup formula alone) so Power Query / pivots can join reliably.

## 2. Naming Convention (unchanged, now formalized)

| Entity | Format | Example | Generation rule |
|---|---|---|---|
| Lead ID | `LD-####` | LD-0001 | Next sequential, zero-padded to 4 digits |
| Client ID | `CL-####` | CL-0001 | Assigned once, on first Booking (not on Lead) |
| Booking ID | `BK-####` | BK-0001 | Sequential across all bookings |
| Invoice No. | `INV-YYYY-####` | INV-2026-0001 | Resets sequence each calendar year |
| Receipt No. | `RCT-YYYY-####` | RCT-2026-0001 | Resets sequence each calendar year |
| Expense No. | `EXP-YYYY-####` | EXP-2026-0001 | Resets sequence each calendar year |

All IDs are generated by a single VBA function (`GenerateID(sheetName)`) reading
the last used number from `19_Settings`, not by `=MAX()+1` formulas scattered
across sheets — avoids collisions when rows are sorted/filtered.

## 3. Sheet-by-Sheet Schema

Legend for **Type**: `Text` `Num` `Date` `Currency` `Dropdown(list)` `Formula` `Lookup(sheet.col)`

### 01_Dashboard
Read-only. No stored data — all cells are formulas/pivot references into other sheets.

| Element | Source |
|---|---|
| Total Leads | `COUNTA(02_CRM_Leads.LeadID)` |
| Conversion Rate | `Bookings / Leads` over selected period |
| Monthly / Yearly Revenue | `SUMIFS(13_Income, Date range)` |
| Outstanding Payments | `SUMIFS(12_Payments, Status="Pending")` |
| Upcoming Weddings | `06_Wedding_Calendar` filtered `EventDate >= TODAY()`, next 30 days |
| Employee Workload | `COUNTIFS(07_Team_Allocation, TeamMember, Status="Active")` |
| Equipment Utilization | `COUNTIFS(08_Equipment, Status="Assigned") / COUNTA(08_Equipment)` |

Refresh trigger: `Workbook_Open` and a manual "Refresh Dashboard" button (VBA
`RefreshAllPivots`), not volatile formulas everywhere — keeps file size/speed sane.

## 4. User Roles (as data, not just doc)

Original spec listed roles descriptively. Made concrete as a table in
`19_Settings.UserRolePermissions`, checked by a `Workbook_Open` macro that
hides/unhides sheet tabs per logged-in user (Windows username via `Environ("Username")`):

| Role | Visible Sheets | Notes |
|---|---|---|
| Admin | All | |
| Manager | 01, 02–07, 12–18 | No Settings edit |
| Editor | 09, 10, 11 | Production only |
| Sales | 01 (limited), 02, 03, 04 | No Finance |
| Accountant | 12–18 | No CRM/Production |

**Caveat carried over from the review:** this is UI-level hiding, not real
security. Anyone with the VBA password (or who copies the file) can see
everything. State this limitation to the client explicitly rather than
implying "Password Protected" means data is safe from a determined user.

## 5. GST / Financial Logic (explicit, per Open Decision #3)

- GST = flat 18%, stored in `19_Settings.GSTRate` (config, not hardcoded).
- Applied to Quotation subtotal only, not to individual expense entries.
- No CGST/SGST split in v1 (add if the business is registered for
  interstate vs. intrastate distinction — confirm with client's accountant).

## 6. Automation — Trigger Table

Every "automatic" bullet from the original spec, now with a defined trigger:

| Feature | Trigger | Mechanism |
|---|---|---|
| Lead/Booking/Client/Invoice/Receipt IDs | On new row save | VBA `GenerateID()` |
| Wedding Countdown | Recalc | Formula, non-volatile (`06_Wedding_Calendar`) |
| Delivery Deadline | On Booking save | Formula from WeddingDate + Settings |
| Payment Reminder | Daily, on file open | VBA checks `12_Payments` for due dates within N days, flags on Dashboard |
| Pending Balance | Recalc | Formula (`05_Bookings.BalanceAmount`) |
| GST Calculation | On Quote save | Formula from Settings.GSTRate |
| Line Item Price Suggestion | On ItemDescription pick, if UnitPrice blank | VBA `ItemCatalog.LookupDefaultPrice()` (`03a_Quotation_LineItems`) |
| Checklist Crew Restriction | On CheckedBy entry | VBA `ChecklistWorkflow.IsAllocatedToBooking()` reverts if not on the booking's crew (`09_Shoot_Checklist`) |
| Checklist Approval Gate | On Approved entry | VBA reverts unless Checked is TRUE; auto-records `ApprovedBy`/`ApprovedAt` (`09_Shoot_Checklist`, decision 0004) |
| Profit Calculation | On demand (Refresh button) | Pivot over 12/14, filtered by BookingID |
| Dashboard Refresh | Manual button + Workbook_Open | VBA `RefreshAllPivots` |
| Conditional Formatting / Status Colors | Native Excel CF rules | No macro needed |
| Data Validation | Native Excel Data Validation | Lists sourced from `19_Settings` |

## 9. Data Validation Rules (previously missing)

- A Booking cannot be created without an existing ClientID.
- Equipment cannot be assigned (Status→Assigned) to two Bookings with
  overlapping EventDates.
- A Team Member cannot be allocated to two Bookings on the same EventDate
  (see §7_Team_Allocation automation).
- Payment.Amount cannot cause `BalanceAmount < 0` without a Refund PaymentType.
- LeadStatus cannot be set to "Lost" without a LostReason.

## 10. Concurrency Note

.xlsm files with VBA disable Excel's real-time co-authoring. If more than one
role needs to edit simultaneously (e.g. Sales entering leads while Accountant
records payments), either:
(a) accept edit conflicts are possible and adopt a "check before you edit" norm, or
(b) split into linked workbooks per role that push/pull via Power Query, or
(c) move off Excel entirely for the shared tables (Leads, Payments) into a
lightweight database with Excel as a reporting front-end.

This is a business decision, not just a technical one — flagged for the client
to choose before build begins.
